# AI 工作流实验室

这个仓库用于学习、实践和改进个人 AI 编程工作流。我希望通过一个持续掌握项目背景的主控会话，把需求澄清、规约、任务派发和验收串起来，让自己主要关注目标、关键决策和交付质量。

仓库中的 GitHub 仓库查询工具是练习项目。它的 CLI 和本机网页既能实际使用，也用来验证新功能、修复和微调是否能回到同一套工作流程。

## 当前工作流

```text
提出需求 → 澄清边界 → 更新 Spec → 拆解任务 → 提交需求基线
                                             ↓
合并 ← 人工验收 ← 主控审计 ← Worker 实现与验证 ← 隔离派发
```

- **主控（Steering）**：理解需求、维护规约和任务、派发工作，并检查交付证据。
- **Worker**：在独立 Git worktree 中按照任务实现和验证，向主控报告结果。
- **人工决策**：确认关键需求，检查实际效果，并在合并前验收。

目前使用 Codex 和 Herdr 实践这套流程。项目的 `steering-flow` Skill 描述了主控行为，包括派发前提交需求基线、在 Herdr 后台 tab 中运行 Worker，以及交付审计。Herdr 的自动选择和布局仍需结合实际会话、权限与工具版本验证；流程不会绕过环境权限或合并确认。

这是一套持续试验的工作流，不同任务的规约、验证和人工参与程度会随着实践调整。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `.agents/skills/steering-flow/` | 主控工作流 Skill 和规约、任务模板 |
| `.agents/skills/herdr/` | Herdr 操作指引 |
| `.openspec/` | 项目规则、需求澄清指引和当前 Spec |
| `docs/pstack/stack.json` | 当前项目的任务记录 |
| `src/` | 练习项目的 CLI、查询服务和本机网页 |
| `test/`、`test-support/` | 自动化测试及浏览器测试辅助代码 |

`stack.json` 是本项目使用的任务记录文件，不表示已经接入独立的 pStack 工具。`.worktrees/` 用于本地隔离工作区，已加入 Git 忽略列表。

## 练习项目：GitHub 仓库查询

练习项目支持通过 CLI 或本机网页查询 GitHub 仓库，按语言、关键词、最低 Stars 等条件筛选，并以 JSON 或表格查看和导出结果。

数据来自 GitHub 官方仓库搜索 API，**不是官方 Trending 榜单**。该 API 不提供当日增长数据，相关字段可能为空。

### 安装与运行

需要安装 Node.js 和 npm。在仓库目录运行：

```sh
npm install
npm start -- --help
```

例如，按最低 Star 数筛选并使用表格输出：

```sh
npm start -- --min-stars 100 --format table
```

启动本机网页：

```sh
npm run web
```

浏览器打开 <http://127.0.0.1:3000>。网页支持设置查询条件、查看结果，并按所选格式下载；不会自动创建导出文件。服务只监听本机 `127.0.0.1`，端口可通过 `PORT` 环境变量设置。

未配置 Token 时也可查询。需要认证时，可在启动前设置 `GITHUB_TOKEN`；网页不会接收或展示 Token。

### 运行测试

```sh
npm test
npm run test:browser
```

浏览器端到端测试默认使用 Windows 上的 Chrome；其他安装位置可通过 `CHROME_PATH` 指定可执行文件。测试使用临时浏览器配置和模拟 GitHub 响应，并验证实际下载文件，不访问 GitHub。
